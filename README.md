# SINERGY Blockchain Budget · Федеральный бюджет РФ в проверяемом распределенном реестре

`blochain_budget` — заготовка отдельного бюджетного домена для блокчейна **СИНЕРГИЯ**: официальный публичный федеральный бюджет России превращается не в одну цифру и не в копию PDF, а в воспроизводимый append-only ledger с доказуемым происхождением каждой версии данных.

## Что уже реализовано в V0.1

- каталог официальных федеральных источников;
- downloader публичных ZIP/XLS/XLSX/CSV/XML/JSON/PDF, которые опубликованы на страницах источников;
- неизменяемый raw-архив с SHA-256 provenance;
- canonical JSON record format;
- все денежные величины — целые **копейки**, без `float`;
- детерминированные `recordMerkleRoot` и `artifactMerkleRoot`;
- локальная append-only цепочка блоков для проверки ingest до публикации в L1;
- `SINERGY:BUDGET` anchor envelope;
- EVM-совместимый `SynergyBudgetAnchorRegistry.sol` для СИНЕРГИИ / постквантового EVM-слоя;
- seed основных параметров федерального бюджета 2026 из 426-ФЗ;
- явная политика: только публичные данные, секретные приложения — metadata reference без попыток доступа;
- тесты инварианта `расходы − доходы = дефицит` для основных параметров 2026.

## Базовые параметры 2026, уже представленные как ledger records

По Федеральному закону от 28.11.2025 № 426-ФЗ:

- доходы: **40 283 269 170 500 ₽**;
- расходы: **44 069 704 164 500 ₽**;
- дефицит: **3 786 434 994 000 ₽**;
- прогноз ВВП: **235 067 млрд ₽**;
- верхний предел внутреннего госдолга на 01.01.2027: **37 436 192 859 500 ₽**.

Seed хранит эти суммы в копейках и сохраняет ссылку на первичный официальный документ.

## Быстрый старт

```bash
python -m venv .venv
. .venv/bin/activate            # Windows: .venv\\Scripts\\activate
pip install -e '.[dev]'
pytest -q
```

### 1. Скачать опубликованные публичные артефакты

```bash
synergy-budget collect
```

Результат:

```text
data/raw/<source-id>/<sha-prefix>--<original-name>
data/manifests/latest.json
```

Большие raw-файлы намеренно не коммитятся в Git. Репозиторий хранит код, manifests и roots; production-узлы СИНЕРГИИ должны реплицировать raw content-addressed store.

### 2. Построить snapshot и локальный блок

```bash
synergy-budget snapshot --as-of 2026-08-21T00:00:00+00:00
```

Создаются:

- `data/manifests/snapshot.json`;
- `data/manifests/anchor.json`;
- `data/ledger/blocks.jsonl`.

### 3. Проверить историю

```bash
synergy-budget verify
```

Любое изменение старого блока ломает hash-chain.

## Что именно переносим на блокчейн

Целевая онтология:

```text
ЗАКОН / ВЕРСИЯ
  ├─ ДОХОДЫ
  ├─ РАСХОДНЫЕ АССИГНОВАНИЯ
  │    └─ ЛИМИТЫ
  │         └─ БЮДЖЕТНЫЕ ОБЯЗАТЕЛЬСТВА
  │              └─ ЗАКУПКА / КОНТРАКТ
  │                   └─ ПЛАТЕЖ / КАССОВОЕ ИСПОЛНЕНИЕ
  ├─ МЕЖБЮДЖЕТНЫЕ ТРАНСФЕРТЫ
  ├─ ГОСПРОГРАММЫ / НАЦПРОЕКТЫ
  ├─ ГОСДОЛГ / ИСТОЧНИКИ ФИНАНСИРОВАНИЯ
  └─ УЧРЕЖДЕНИЯ / ГРБС / КБК / КЛАССИФИКАТОРЫ
```

Каждая сущность имеет источник, временную версию и hash. Ничего не перезаписывается задним числом.

## Почему «все хранится в распределенном реестре» не означает «195 MB PDF кладем в storage Solidity»

Для СИНЕРГИИ правильная схема двухслойная:

1. **Data availability / archive nodes:** полные исходные файлы, разбитые на content-addressed chunks и реплицированные между узлами.
2. **Consensus ledger:** нормализованные бюджетные события + SHA-256 артефактов + Merkle roots + provenance + версия.

Так весь публичный набор проверяем и воспроизводим, но state блокчейна не раздувается гигантскими бинарными файлами. Если L1 СИНЕРГИИ получит собственный blob/data-availability слой, raw chunks можно сделать нативной частью протокола без изменения модели данных.

## Граница публичности

Публичный текст закона содержит ссылки на приложения с грифами «секретно» и «совершенно секретно». SINERGY Blockchain Budget **не пытается получать их содержимое**. Вместо этого ledger сохраняет `RESTRICTED_REFERENCE`: существование приложения, его правовой источник и факт недоступности публичному контуру.
