# V0.2 Data Engine: Казначейство → КБК → reconciliation → ЕИС → граф

## 1. Реальные форматы

V0.2 читает CSV/TXT, XLSX, legacy XLS и ZIP с вложенными табличными файлами. XLSX разбирается через `openpyxl`, XLS — через `xlrd`. ZIP обрабатывается без распаковки непроверенных путей на диск; установлены ограничения на число файлов и суммарный несжатый размер.

Денежные значения переводятся в целые копейки через `Decimal`, а не `float`.

## 2. КБК расходов

Двадцатизначный код расходов разбирается как:

- 1–3: ГРБС;
- 4–5: раздел;
- 6–7: подраздел;
- 8–17: целевая статья;
- 18–20: вид расходов.

Целевая статья дополнительно делится на программную/непрограммную статью (первые 5 символов) и направление расходов (последние 5).

## 3. Normalizer Казначейства

`synergy-budget normalize` ищет строку заголовков в листе, распознаёт типовые поля КБК и денежные колонки. Из одной строки отчета формируются отдельные immutable records для:

- бюджетных ассигнований;
- лимитов бюджетных обязательств;
- бюджетных/денежных обязательств;
- кассового исполнения;
- исполнения доходов.

Provenance включает source id, имя архива/вложенного файла, лист, строку, денежную колонку и SHA-256 исходного артефакта.

## 4. Исторический backfill

```bash
synergy-budget backfill --source treasury-federal-budget --from-year 2013 --to-year 2026
```

Backfill intentionally fail-closes on year attribution: `report_year` остаётся `null`, если год нельзя подтвердить URL/именем файла. Запрошенный фильтр года сам по себе не является доказательством — это защищает от ситуации, когда государственный сайт игнорирует query-параметр и возвращает текущий год.

Артефакты с `report_year=null` архивируются, но не должны автоматически нормализоваться как данные запрошенного года.

## 5. Reconciliation

```bash
synergy-budget reconcile --input data/normalized/treasury.jsonl
```

Сверка строится по полному ключу КБК. Отдельно хранятся ассигнования, ЛБО, обязательства и кассовое исполнение. Контрольный план = ЛБО, если они опубликованы, иначе ассигнования. Это исключает ошибочное двойное суммирование ассигнований и лимитов.

Статусы: `EXACT`, `UNDER_EXECUTED`, `OVER_EXECUTED`, `MISSING_PLAN`, `NO_ACTIVITY`.

## 6. ЕИС закупок

`synergy_budget.eis` принимает публичные XML или ZIP/XML выгрузки контрактного реестра и формирует `PROCUREMENT_CONTRACT` с реестровым номером, номером контракта, ИНН заказчика/поставщика, ценой и КБК, если он присутствует.

```bash
synergy-budget eis export.zip --year 2026
```

Transport/download adapter отделён от XML normalizer: изменение публичного способа выдачи ЕИС не должно менять каноническую модель данных.

## 7. Граф движения бюджетного рубля

```bash
synergy-budget graph --input data/normalized/treasury.jsonl
```

Граф содержит типы узлов `BUDGET_YEAR`, `GRBS`, `BUDGET_LINE`, `CONTRACT`, `RECIPIENT`, `PAYMENT` и связи `APPROPRIATES`, `CLASSIFIES`, `FUNDS`, `AWARDED_TO`, `SETTLED_BY`.

Следующий строгий мост — reconciliation ЕИС ↔ Казначейство по КБК + заказчику + периоду + сумме и подключение публичных идентификаторов фактических казначейских платежей там, где они официально публикуются.
